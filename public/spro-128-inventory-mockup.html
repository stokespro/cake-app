PROPOSED · RECOMMENDED

Strain × format matrix

Rows = strain (alphabetical, fixed). Columns = format (Eighth → Half → Variety → Bites, fixed). Order never changes on realtime refresh — a packager builds muscle memory for "Bacio Gelato is row 2" the same way they already know a spreadsheet. Staged is the dominant number in each cell (it's the one packaging acts on); cased/filled drop to a small secondary line. A Needs Attention strip above the grid surfaces every gap/restage/low SKU so urgency is visible without destroying the stable layout underneath it.

Why this works

  • Stable spatial memory. Strain rows sort alphabetically and never reorder on realtime updates — the opposite of today's arbitrary Object.keys() order.
  • Staged gets the visual weight. It's promoted to a large number; cased/filled become a quiet C· F· line — three equal-sized 10px numbers repeated 28 times today is noise, not signal, for a department whose main question is "is something staged and ready to package next."
  • Three empty states, not one. Hatched = format doesn't exist for that strain (Aloha Sugar has no Eighth/Half/Bites SKU). Dashed = SKU exists but is status ≠ 'active' (6 of the 7 Half SKUs today). Solid neutral = active, tracked, genuinely at zero with no demand. Today all three collapse into "card doesn't render" or "shows 0" — you can't tell which case you're looking at.
  • Blind spot fixed. staged === 0 & pending > 0 is now its own amber "RESTAGE" state, distinct from "LOW" (0<staged<4) and "SHORT" (gap>0) — same 3-color system, no new hue, just a state that used to render nothing.
  • No ragged heights. Every cell is a fixed-size box; the pending-orders count moves to a small corner pill that overlays rather than adding a line, so it never changes cell height.
  • Column scanning. "How are our Variety packs doing" — one column, one glance. Today those 8 SKUs are scattered across 16 unsorted A-Buds cards with nothing tying them together visually.

ALTERNATIVE · REJECTED

Demand-sorted "what needs work now"

Same fixed-cell component, same blind-spot fix, but no matrix — a single flat list sorted by urgency (SHORT → RESTAGE → LOW → OK → idle), worst first. This is what a "just show me what's on fire" view looks like.

Why it's not the primary view

  • Reorders itself constantly. Every inventory tick or new order can move every card's position. On a shared packaging-room display, staff rely on "BG-B is always third row, second card" — this design guarantees that never stays true for more than a few minutes.
  • Loses the taxonomy entirely. You can no longer scan "how's Bacio Gelato doing across all formats" or "how are Variety packs doing overall" — both real questions the department asks, per Joshua's original ask.
  • Redundant with the strip. The one thing this view is genuinely good at — surfacing SHORT/RESTAGE/LOW — is already covered by the Needs Attention strip on the matrix, with none of the reordering cost.

Recommendation

Ship the strain × format matrix with the Needs Attention strip, not a toggle between two views. The alternative's only real advantage — urgency-first scanning — is already delivered by the strip, at zero cost to layout stability. A toggle would mean maintaining two sort orders and two mental models for a 28-cell grid; not warranted here.

Ship this as the desktop matrix table and mobile per-strain rows shown above. No toggle, no view switch.
